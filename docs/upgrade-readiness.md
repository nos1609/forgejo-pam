# Готовность к обновлению Forgejo: 15.0.10 и 16

## Назначение

Документ собирает то, что нужно знать до следующего обновления пакета `forgejo`:
что уже исправлено между установленной версией и текущей, чего ждать от 15.0.10
и что изменится при переходе на 16 и дальше. Это рабочая заметка с датой, а не
инструкция: порядок сборки, установки и отката задаёт
[`operations.md`](operations.md). Заметка не разрешает изменение боевого контура.

Версия Forgejo в этом репозитории берётся из Fedora dist-git. Решение о смене
линии выпусков принимает Fedora, этот репозиторий переносит на неё свою дельту.

- Fedora ведёт `rawhide` и `f45` по линии 15.0 (LTS). 15.0.10 придёт тем же

  этого репозитория на четыре.
- Успешные COPR-сборки подтверждены только для 15.0.7 (см. `docs/README.md`).

## Что уже исправлено между 15.0.3 и 15.0.9

Исправления безопасности есть в пяти выпусках из шести. Два помечены исходным
проектом как Critical.

| Выпуск | Безопасность | Actions и журналы |
| --- | --- | --- |
| [15.0.4](external/forgejo/2026-10-05/release-notes-15.0.4.md) | кэш права записи при первой отправке ссылки; списки разрешённых и запрещённых узлов для миграций | не удалять журналы задач, которых нет |
| [15.0.5](external/forgejo/2026-10-05/release-notes-15.0.5.md) | объявление о CVE-2026-20896, см. ниже | — |
| [15.0.6](external/forgejo/2026-10-05/release-notes-15.0.6.md) | hooks при применении patch; `100.64.0.0/10` в правиле `private`; чтение файлов через org-mode; хранимый XSS в ошибках Actions | зависшие задания при медленном `FetchTask`; поиск заданий только там, где Actions включены |
| [15.0.7](external/forgejo/2026-10-05/release-notes-15.0.7.md) | обход ограничений токена в `/pulls/{index}/update`; reusable workflows при `pull_request_target` раскрываются из базовой ветки; запрет `owner` как режима доступа соавтора | срок хранения журнала без файла; panic при отсутствии файла в DBFS; дрейф триггера `pull_request` |
| [15.0.8](external/forgejo/2026-10-05/release-notes-15.0.8.md) | **Critical:** раскрытие шаблона при создании репозитория; проверка прав при правке чужой ветки через API; вложения черновых релизов; команда `admin` получала права `owner` | показывать журналы задания, если они есть |
| [15.0.9](external/forgejo/2026-10-05/release-notes-15.0.9.md) | **Critical:** `ApplyDiffPatch` менял конфигурацию bare-репозитория; CSRF при привязке OpenID | — |

Изменение требований сборки: до 15.0.7 включительно `go.mod` объявляет
`go 1.25.0`, с 15.0.8 — `go 1.26.0`. Spec в Fedora по-прежнему пишет
`golang-bin >= 1.23`, так что фактическое требование жёстче объявленного в spec.
EL10 AppStream на 5 октября 2026 года даёт `golang-1.26.7-2.el10_2`, этого
достаточно.

## Чего ждать от 15.0.10

Веха `Forgejo v15.0.10` в исходном проекте открыта, срок не назначен. В ветке
`v15.0/forgejo` после 15.0.9 на 5 октября 2026 года лежат одиннадцать коммитов.
Значимые для этого контура:

- меньше памяти при загрузке журналов и артефактов Actions (#14654);
- `workflow_dispatch` отвечает 4xx на неизвестную ссылку или workflow (#14617);
- расписания отключаются только при устойчивой ошибке разбора (#14507);
- состояние ветки в базе не откатывается при одновременных push (#14682);
- удаление пользователя с токеном доступа к отдельным репозиториям (#14622).

### Журналы Actions, которые не доходят до хранилища

Это исправление боевой контур ждёт больше остальных, и его попадание в 15.0.10
не гарантировано.

Дефект: `UpdateLog` в `routers/api/actions/runner/runner.go` выходит раньше, чем
обрабатывает признак `NoMore`, если последний запрос раннера не несёт новых
строк. Журнал такой задачи остаётся в базе (DBFS). Страдают только успешные
задачи: упавшая заканчивается строкой с ошибкой. Дальше журнал ждёт
обслуживающую задачу `transfer_lingering_logs`: она запускается в полночь и
берёт только задачи старше 24 часов, порог зашит в код. Итог — задержка от 24 до
48 часов.

Замер на боевом экземпляре с 22 сентября по 5 октября 2026 года: в дни с
активностью Actions так задерживалось от 4% до 21% задач, у которых есть журнал.
До переноса журнал виден только в интерфейсе Forgejo: в линии 15.0 нет REST API
журналов, и читатели файлового хранилища его не находят.

Состояние исправления ([снимок](external/forgejo/2026-10-05/pull-14689.md)):

- слито в основную ветку исходного проекта 4 октября 2026 года (#14689, коммит
  `93c69ff3dd`);
- перенесено в `v17.0/forgejo` (#14709);
- имеет метку `backport/v15.0/forgejo`, но на 5 октября 2026 года запроса на
  перенос в `v15.0/forgejo` нет и в ветке исправления нет;
- метки для `v16.0/forgejo` нет.

Проверка, есть ли исправление в ветке или в теге:

```bash
curl -fsS https://codeberg.org/forgejo/forgejo/raw/branch/v15.0/forgejo/routers/api/actions/runner/runner.go | grep -c emptyRows
curl -fsS https://codeberg.org/forgejo/forgejo/raw/tag/v15.0.10/routers/api/actions/runner/runner.go | grep -c emptyRows
```

`0` означает, что исправления нет. Вторая команда заработает после появления
тега.

Если 15.0.10 выйдет без исправления, остаются два пути: ждать следующего выпуска
линии или добавить исправление в spec отдельным patch. Автоматический перенос
может не пройти, потому что в 15.0 эта функция устроена иначе; готовый patch
лежит по адресу `https://codeberg.org/forgejo/forgejo/pulls/14689.patch`. На
5 октября 2026 года владелец контура patch не выбирал.

## Подготовка сборки 15.0.10

1. Дождаться версии в Fedora dist-git:

   ```bash
   curl -fsS https://src.fedoraproject.org/rpms/forgejo/raw/rawhide/f/forgejo.spec | grep '^Version:'
   ```

2. Сверить требование `go` нового тега с тем, что дают chroot:

   ```bash
   curl -fsS https://codeberg.org/forgejo/forgejo/raw/tag/v15.0.10/go.mod | grep -E '^(go|toolchain) '
   dnf -q repoquery --available --latest-limit 1 --qf '%{name}-%{version}-%{release}' golang
   ```

   Сборка идёт без сети, поэтому недостающий toolchain скачать нельзя: версия
   `golang` в chroot должна быть не ниже директивы `go`.

3. Перенести дельту упаковки на новый commit Fedora dist-git. Между spec Fedora
   15.0.9 и spec этого репозитория 15.0.7 расходятся 59 строк; `Patch0` у обоих
   один и тот же.
4. Собрать в COPR для `epel-10-x86_64` и `fedora-45-x86_64` и проверить RPM до
   установки по [`operations.md`](operations.md).

## Что проверить перед установкой на боевой контур

Установка пойдёт с 15.0.3, поэтому действуют изменения всех выпусков сразу.

| Изменение | С какого выпуска | Что проверить |
| --- | --- | --- |
| `100.64.0.0/10` считается частной сетью | 15.0.6 | Вебхуки, миграции и зеркала на адреса CGNAT, включая оверлейные сети: `[webhook] ALLOWED_HOST_LIST`, `[migrations] ALLOW_LOCALNETWORKS` |
| Строже проверка узлов при миграции и зеркалировании | 15.0.4 | `[migrations] ALLOWED_DOMAINS`, `BLOCKED_DOMAINS`, `ALLOW_LOCALNETWORKS` |
| CVE-2026-20896 требует ручного действия | 15.0.5 | Касается только контейнерных установок с аутентификацией через обратный прокси. RPM-установка без `ENABLE_REVERSE_PROXY_AUTHENTICATION` не затронута; на 5 октября 2026 года параметр на боевом экземпляре не задан |
| Локальные reusable workflows при `pull_request_target` берутся из базовой ветки | 15.0.7 | Workflows с `pull_request_target`, которые вызывают reusable workflow из того же репозитория |
| Удалено срезание EXIF | 15.0.4 | Только если на него полагались |

Проверка параметра из третьей строки, путь к `app.ini` подставить свой:

```bash
sudo grep -n -E '^\s*(ENABLE_REVERSE_PROXY_AUTHENTICATION|REVERSE_PROXY_TRUSTED_PROXIES)\s*=' <app.ini>
```

В заметках к выпускам 15.0.4–15.0.9 миграции базы не упомянуты. Это не
доказывает, что их нет: резервная копия базы и `app.ini` обязательна, как
требует `operations.md`.

## Проверка после установки

К проверкам из `operations.md` добавить одну, если в установленной версии есть
исправление журналов. Запустить workflow, дождаться успешного завершения и
убедиться, что журнал ушёл в хранилище сразу:

```bash
sudo sqlite3 -readonly <база Forgejo> \
  "select count(*) from action_task where status=1 and log_length>0 and log_in_storage=0 and stopped > strftime('%s','now','-1 hour');"
```

Ожидается `0`. Запрос написан для SQLite; `status=1` — успешная задача.

## Откат

Порядок задаёт `operations.md`. Для этого обновления важно одно: разрыв в семь
выпусков проверяется только на копии. `dnf downgrade` без восстановления базы из
той же резервной копии откатом не считается.

## Подготовка к 16 и к уходу с линии LTS

### Сроки

16.0 снимается с поддержки 29 октября 2026 года, через две недели после выхода
17.0.0. Переход именно на 16 к этому моменту уже не имеет смысла: при уходе с
LTS целью станет 17.0 (до 28 января 2027 года), затем 18.0 и 19.0 (LTS, выпуск
15 апреля 2027 года). Вне LTS основную версию придётся менять каждые три месяца.

На 5 октября 2026 года Fedora `rawhide` остаётся на 15.0.9, хотя 16.0 вышла
16 июля 2026 года. Когда Fedora сменит линию, неизвестно. Проверка та же, что в
шаге 1 подготовки сборки.

### Ломающие изменения 16.0.0

Полный список — в [заметках к выпуску](external/forgejo/2026-10-05/release-notes-16.0.0.md).

| Изменение | Что проверить |
| --- | --- |
| Из конфигурации контейнерного образа убрано `REVERSE_PROXY_TRUSTED_PROXIES = *` | RPM не затронут. Если аутентификация через обратный прокси включена, параметр задать явно |
| Проверка узлов при миграции и зеркалировании | То же, что для 15.0.4 |
| `${{ forgejo.ref }}` в workflows по расписанию получает правильное значение | Workflows с `on: schedule`, которые читают `ref` |
| Поле `url` у pull request в REST API содержит адрес API | Потребители REST API, которые читают это поле |

### Новое в 16.0.0, значимое для контура

- REST API журналов Actions:
  `GET /repos/{owner}/{repo}/actions/jobs/{job_id}/logs` отдаёт текст журнала
  одного задания, `GET /repos/{owner}/{repo}/actions/runs/{run_id}/logs` — архив
  журналов всего прогона. Чтение журнала по токену становится штатной
  возможностью Forgejo и не зависит от того, перенесён ли журнал в файловое
  хранилище. Внешний шлюз чтения журналов из хранилища после этого можно
  упростить или заменить; решение не принято.
- `GET /repos/{owner}/{repo}/actions/runs/{id}/jobs`, REST API артефактов,
  отмена прогона через API, удаление прогонов.
- Ручная приоритизация прогонов. Значимо при одном раннере на все репозитории.
- Условие `if` задания вычисляется на сервере, когда это возможно.

### Сборка

| Требование | 15.0.9 | 16.0.5 | Ветка `v17.0/forgejo` | EL10 на 5 октября 2026 года |
| --- | --- | --- | --- | --- |
| Директива `go` | 1.26.0 | 1.26.0 | 1.26.0 | `golang-1.26.7-2.el10_2` |
| Директива `toolchain` | 1.26.7 | 1.26.7 | 1.26.8 | — |
| `engines.node` | `>= 20.0.0` | `>= 20.0.0` | `>= 20.0.0` | `nodejs-22.23.2-1.el10_2` |

По требованиям к `go` и Node препятствий нет. Директива `toolchain` выше версии
в chroot сборке не мешает, пока выполняется директива `go`.

Не проверено и проверяется только чистой сборкой в COPR:

- применимость `forgejo-14.0.2-app.ini.tmpl.patch` к 16 и 17;
- сборка с тегом `pam` и вендоринг через `go-vendor-tools`;
- совместимость установленного раннера: линия 16.0 собирается с модулем раннера
  v12.13.x, на боевом контуре 5 октября 2026 года стоит раннер v12.11.1.

### База данных

Смена основной версии выполняет миграции базы. Обратной миграции нет: откат
возможен только восстановлением базы и `app.ini` из одной резервной копии вместе
с прежним RPM.
