# Стандарт документации

Этот документ задаёт правила для `forgejo-pam`. Код, команды, RPM macros,
идентификаторы SELinux и официальные имена по этим правилам не переименовывают.

## Приоритет

При конфликте используйте источники в таком порядке:

1. фактический код, spec и опубликованный результат сборки;
2. `docs/architecture.md` и `docs/operations.md`;
3. `docs/acceptance-traceability.md`;
4. корневые README и справочный текст.

Расхождение между документацией и кодом исправляйте явно. Не называйте план
реализованным состоянием.

## Язык и структура

- Пишите основной `README.md` и новые рабочие документы по-русски.
- Синхронизируйте `README.en.md` и `NOTICE.en.md` по смыслу с русской версией.
- Сначала указывайте назначение и фактический статус, затем детали.
- Отделяйте сборку пакета от установки и проверки работающего сервиса.
- Для инфраструктурной операции указывайте подготовку, применение, проверку и
  откат.
- Приводите команды для запуска из корня репозитория.
- Не используйте абсолютный путь конкретного хоста в публичной инструкции.
- Не публикуйте секреты, персональные данные и адреса рабочих узлов.
- Указывайте дату для меняющихся версий, веток и статусов сборок.

## Термины

Сохраняйте официальные имена `Forgejo`, `Fedora`, `EPEL`, `COPR`, `RPM`, `PAM`,
`SELinux`, `systemd`, `CodeQL` и `CodeRabbit`. Используйте:

| Не использовать без необходимости | Писать |
| --- | --- |
| `прод` | `боевой контур` |
| `билд` | `сборка` |
| `деплой` | `развёртывание` или `установка` по смыслу |
| `live` | `работающий` или `боевой` по смыслу |
| `upstream` без пояснения | `исходный проект` или точное имя источника |
| `rollback` | `откат`; имя команды или файла сохранять |
| `green` | точный успешный тест или статус |

## Доказательства

Успешный статус COPR подтверждает только указанный build ID и chroot. Локальная
сборка не заменяет чистый chroot. Наличие RPM не подтверждает PAM-вход,
git-over-SSH, миграцию базы данных и откат на конкретном сервере.

Архитектурные схемы оформляйте блоком `mermaid`. Деревья файлов, команды и
выводы оформляйте блоком с точным языком.
